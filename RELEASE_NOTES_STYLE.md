# Solitaire release notes style

Preserve the origin breadcrumb at the top of `RELEASE_NOTES.md`. Immediately
after it, use `# Release yyyy-MM-dd-HH-mm`, matching the bare UTC timestamp tag.
Do not add a `v` prefix.

## Required sections

- `## Overview`: one or two factual sentences describing this release.
- `## Installation`: open https://solitaire.ignyos.com/; describe PWA installation
  only when supported by the release evidence.
- `## Requirements`: modern browser; HTTPS for service worker/offline functionality.
- `## Documentation`: link to the repository README and relevant user documentation.

## Optional sections

Use New Features, Improvements, Bug Fixes, Technical Changes, and Breaking Changes
only when the release evidence supports them. Omit empty sections.

## Evidence and writing rules

- Read the entire `release/rel-<timestamp>.txt` and the released PM items.
- Replace the previous release body; do not carry unrelated old release notes forward.
- Describe only shipped changes visible in the diff. A PM plan is not proof of implementation.
- Never describe the initial scaffold as a playable game.
- Use concise, user-facing language and present-tense verbs; one change per bullet.
- Prefer `- **Area**: Adds/Fixes/Improves ...` and explain user impact.
- Do not claim remote deployment, DNS, or cross-browser support without verification.
